# ТЗ: Windows-приложение «Чат» (десктоп-клиент)

## 1. Цель
Нативное Windows-приложение для операторов и администраторов: быстро видеть новые сообщения, читать и отправлять сообщения с вложениями в общий и личные чаты. Приложение работает в трее и уведомляет о новых сообщениях.

## 2. Рекомендуемый стек
- C# / .NET 8, WPF (или WinUI 3). Допустимо: Electron + TypeScript.
- HTTP: HttpClient. JSON: System.Text.Json.
- Локальное хранение: настройки в `%AppData%\ChatApp\settings.json`; пароль хранить через Windows DPAPI (ProtectedData), не в открытом виде.
- Установщик: MSIX или Inno Setup. Автозапуск с Windows (опционально, настройка).

## 3. Серверный API
Базовый URL: `https://functions.poehali.dev/614f76d4-2339-46e5-ba86-05ee47904320`

Авторизация в каждом запросе — заголовки:
- `X-User-Id`: логин
- `X-Auth-Token`: пароль

Доступ только у пользователей с правами администратора или оператора. Все ответы — JSON. Ошибки: `{"error": "текст"}` (на русском, показывать пользователю как есть).
Коды: 401 неверный логин/пароль, 403 нет доступа, 429 слишком много неудачных попыток (подождать 15 минут), 400 ошибка данных.

### 3.1 Список собеседников и данные о себе
`GET ?action=users`
```json
{"me": {"id": 1, "name": "Иван", "role": "operator|admin"},
 "users": [{"id": 2, "name": "Пётр", "role": "admin"}]}
```
Используется также для проверки логина/пароля при входе.

### 3.2 Проверка новых сообщений (лёгкий опрос)
`GET ?action=check&after_id=N`
```json
{"new_count": 3, "private_count": 1, "last_id": 152,
 "senders": [{"sender_name": "Пётр", "channel": "private", "count": 1}],
 "me": {...}}
```
- Считаются только чужие сообщения с id > N, доступные пользователю.
- `new_count = 0` — ничего нового.
- Вызывать каждые 5–10 секунд (настройка). Не загружает тексты и файлы.

### 3.3 Получение новых сообщений
`GET ?action=messages&after_id=N&limit=100`
```json
{"messages": [{
  "id": 153, "channel": "general|private",
  "sender_id": 2, "sender_name": "Пётр", "sender_role": "admin|operator",
  "recipient_id": null, "recipient_name": null,
  "text": "Привет", "file_url": "https://...|null", "file_name": "doc.pdf|null", "file_size": 12345,
  "created_at": "2026-11-02 14:05:00", "is_mine": false}],
 "last_id": 153, "me": {...}}
```
Сообщения по возрастанию id. Если вернулось ровно `limit` — запросить следующую порцию с `after_id = last_id`.

### 3.4 История (подгрузка старых при прокрутке вверх)
`GET ?action=history&before_id=N&limit=50` (без `before_id` — самые последние)
Ответ: `{"messages": [...по возрастанию...], "has_more": true}`

### 3.5 Отправка сообщения
`POST` с `Content-Type: application/json`
```json
{"action": "send", "text": "Текст", "channel": "general",
 "recipient_id": 2,
 "file": {"name": "report.pdf", "type": "application/pdf", "content": "<base64>"}}
```
- `channel`: `general` (общий) или `private` (тогда обязателен `recipient_id`).
- `text` или `file` — достаточно одного. Текст до 4000 символов.
- Файл: base64 без префикса `data:`; максимум 4 МБ (проверять на клиенте до отправки).
- Оператор может писать лично только администраторам.
- Ответ: `{"message": {...как в 3.3}}`

### 3.6 Вложения
`file_url` — публичная ссылка (CDN), скачивается обычным GET без авторизации. Приложение скачивает файл по клику в `%UserProfile%\Downloads\ChatApp\` и открывает/показывает в папке. Изображения (jpg, png, gif, webp) показывать миниатюрой в ленте.

## 4. Функциональные требования

### 4.1 Вход
- Окно входа: логин, пароль, галочка «Запомнить меня».
- Проверка через `action=users`. При успехе сохранить учётные данные (пароль — DPAPI).
- При 401 в любой момент — вернуть на экран входа с сообщением.
- Кнопка «Выйти» стирает сохранённые данные.

### 4.2 Главное окно
- Слева: список чатов — «Общий чат» и личные чаты с собеседниками из `users`. Бейдж с количеством непрочитанных у каждого чата.
- Справа: лента сообщений выбранного чата, внизу поле ввода, кнопка скрепки (вложение), кнопка «Отправить» (Enter — отправить, Shift+Enter — перенос строки).
- Сообщения: имя, время, текст; свои — справа и другого цвета. Ссылки в тексте кликабельны.
- Вложение: иконка + имя + размер, кнопки «Открыть» и «Сохранить как…». Для изображений — миниатюра, клик — просмотр.
- Прикрепление: через диалог выбора файла, перетаскиванием в окно и вставкой из буфера (Ctrl+V для скриншотов; имя `screenshot_YYYYMMDD_HHmmss.png`). Перед отправкой показывать превью/имя файла и крестик отмены.
- Личный чат = сообщения с `channel=private`, где собеседник — отправитель или получатель. Общий чат = `channel=general`.
- Прокрутка вверх подгружает историю (`history`). Автопрокрутка вниз при новых сообщениях, если пользователь был внизу.

### 4.3 Фоновая проверка и уведомления
- Таймер опроса `check` с `after_id = last_id` (последний известный id). Интервал по умолчанию 7 сек, настраивается 3–60 сек.
- При `new_count > 0` — запросить `messages`, добавить в ленту, обновить бейджи.
- Windows-уведомление (toast): «Имя: текст» (для файла — «Имя: 📎 имя_файла»). Клик по уведомлению открывает нужный чат. Не показывать уведомление, если окно активно и открыт этот же чат.
- Приложение сворачивается в трей при закрытии окна (настройка). Иконка в трее меняется при непрочитанных; в подсказке — число непрочитанных. Меню трея: «Открыть», «Не беспокоить», «Выход».
- Звук уведомления (вкл/выкл).
- «Не беспокоить» отключает toast и звук, бейджи остаются.
- При первом запуске `last_id` = id последнего сообщения из `history` (не засыпать уведомлениями о старом); хранить `last_id` и «прочитанность» по чатам в локальных настройках.
- При потере сети: статус «Нет соединения» в окне, повтор с нарастающей паузой (до 60 сек), по восстановлении — догрузить пропущенное.

### 4.4 Отправка
- Сообщение сразу появляется в ленте со статусом «отправляется»; при ошибке — красная отметка и кнопка «Повторить».
- Не допускать двойной отправки (блокировать кнопку на время запроса).
- Проверка размера файла > 4 МБ — сообщение «Файл больше 4 МБ» без запроса.
- Прогресс-индикатор при отправке файла.

### 4.5 Настройки
Интервал опроса, автозапуск, сворачивание в трей, звук, папка загрузок, тема (светлая/тёмная/системная).

## 5. Нефункциональные требования
- Один экземпляр приложения (повторный запуск открывает существующее окно).
- Потребление: в фоне менее 80 МБ ОЗУ, нагрузка CPU близка к нулю между опросами.
- Все тексты интерфейса на русском. Время показывать в локальной зоне пользователя (сервер отдаёт время как есть, формат `YYYY-MM-DD HH:mm:ss`).
- Сетевые таймауты 15 сек (отправка файла — 60 сек).
- Пароль и данные не писать в логи. Лог ошибок — `%AppData%\ChatApp\logs`, ротация.
- HTTPS только.

## 6. Структура проекта (рекомендация)
- `Api/ChatApiClient` — методы `GetUsers`, `Check`, `GetMessages`, `GetHistory`, `Send`.
- `Services/PollingService` — таймер опроса, события «новые сообщения», «ошибка сети».
- `Services/NotificationService` — toast, трей, звук.
- `Services/SettingsStore` — настройки, DPAPI.
- `ViewModels` (MVVM): Login, Main, ChatList, ChatView, Settings.
- `Views`: окна и контролы.

## 7. Критерии приёмки
1. Вход с верными данными работает, с неверными показывает ошибку с сервера.
2. Сообщение, отправленное с сайта, появляется в приложении за время не больше интервала опроса и вызывает уведомление.
3. Отправка текста, файла до 4 МБ и скриншота из буфера в общий и личный чат работает; получатель видит вложение на сайте.
4. Вложения от других скачиваются и открываются.
5. После перезапуска приложения старые сообщения не вызывают уведомлений, непрочитанные сохраняются.
6. При отключении сети приложение не падает и догружает сообщения после восстановления.
7. Приложение работает в трее и не запускается вторым экземпляром.

## 8. Вне объёма
Редактирование и удаление сообщений, групповые чаты, шифрование end-to-end, push-уведомления при закрытом приложении, версии для macOS/Linux.
